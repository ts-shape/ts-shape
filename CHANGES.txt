# August 18, 2026
add: ts_shape.reporting -- a new top-level package for production reporting across
  global facilities. The event packs answer questions about one asset; this layer
  consolidates their per-site KPI frames into regional and global figures. Ten
  modules, all re-exported from ts_shape and held to strict typing:
  * Facility / FacilityRegistry -- site master data (timezone, region, currency,
    shift pattern, working days, capacity) plus validate(), which reports the
    defects that silently corrupt a consolidated report: an unresolvable
    timezone, a missing region, and shift patterns that overlap (readings
    counted twice) or leave a gap (readings counted nowhere).
  * FacilityCalendar -- each site's own local production day, shift and reporting
    period from UTC input, using real IANA zones. period_grid() emits the
    expected facility x period calendar with exact UTC bounds, so a local day is
    23 or 25 hours long across a DST boundary instead of a fixed offset that
    shifts a whole shift across it; utc_window() maps a site-local window back to
    the UTC range to query.
  * AssetHierarchy -- the ISA-95 equipment tree (region / site / area / line) with
    validate() for multiple_parents (a node counted once per parent inflates the
    enterprise total), missing_parent and duplicate_leaf, plus enrich() and
    roll_up() along the levels.
  * MetricSpec / aggregate_metrics -- explicit per-metric aggregation semantics:
    sum for quantities, ratio for a rate recomputed from summed components
    (exact), weighted_mean for a rate weighted by its own exposure. The
    unweighted mean of a rate is the classic consolidation defect -- one plant at
    95% for 30 minutes and two at 60% for three shifts average to 77.5%
    unweighted and 60.2% weighted by planned minutes.
  * FleetRollup -- total / by_facility / by_period / by(dimensions) /
    consolidate() (global + region + site stacked in one frame), plus
    contribution() (Pareto across sites) and pivot() (site x period matrix).
    Every aggregate carries `contributors`, the number of facilities behind it.
  * MetricNormalizer -- currency conversion to one reporting currency (flat or
    period-dated rates applied as-of, keeping the source figures and the fx_rate
    used), per-unit / per-hour / per-capacity exposure normalisation, unit
    rescaling, and index-to-baseline.
  * FacilityBenchmark -- rank (percentile, quartile, z-score, gap to best and
    median), quartiles, opportunity() (the gap to the top quartile expressed in
    exposure units rather than percentage points), a normalised 0-100 scorecard,
    stability() (a plant averaging 70% every week and one alternating 40% and
    100% rank identically on the mean), and outliers().
  * VarianceBridge -- facility_bridge() for per-site contributions to a fleet
    delta, and rate_bridge(), which splits a change in a weighted fleet rate
    into rate effect, mix effect and interaction that sum exactly to the observed
    change. This is what answers "the fleet rate fell although every plant
    improved": volume moved to a weaker site. Also plan_vs_actual() and
    period_over_period().
  * ReportingCoverage -- completeness, explicit missing facility/period rows,
    per-column null rates and freshness against an expected calendar. A total
    computed over 34 of 37 plants looks exactly like one over all 37; without an
    expected grid a silent site is invisible.
  * GlobalScorecard / KpiTarget -- per-target direction, tolerance, weight and
    aggregation; evaluate / facility_summary / fleet_summary / trend. A site with
    no data reports no_data rather than passing by omission, and fleet_summary
    reports facilities_at_risk next to the fleet value, because a green fleet
    number with two of three plants below target is the most common way a
    consolidated scorecard misleads.
  Docs: new guide (guides/global-reporting.md), 10 module pages, and a runnable
  self-contained demo (examples/global_reporting_demo.py).
build(mypy): ts_shape.reporting.* lands directly in the strict allowlist

# July 31, 2026
add: OEECalculator.calculate_oee now threads handle_resets to its performance
  and quality components and max_gap to its availability/performance components.
  Previously the top-level OEE could not benefit from reset handling, so a day
  with a counter reset silently dragged OEE toward zero; and availability booked
  a logging/overnight gap (last state = running) as run time. calculate_availability
  and calculate_performance gained a max_gap kwarg. Output schema unchanged.
add: opt-in max_gap on RuntimeAccountingEvents.runtime_summary,
  runtime_per_window, and operating_hours_meter -- a gap to the next sample
  longer than max_gap is treated as a logging outage and excluded, so it no
  longer inflates run time, utilization, or the hour meter.
fix: LineThroughputEvents.throughput_oee honored the documented
  availability_threshold parameter, which was previously accepted but ignored.
  A window now counts as available when its part count reaches
  availability_threshold x target_rate; the new default 0.0 reproduces the old
  "produced anything" behaviour. throughput_oee also gained handle_resets
  (threaded to count_parts).
add: opt-in infer_dwell_from_next on the traceability timelines
  (OrderTraceabilityEvents.build_timeline / current_status /
  station_dwell_statistics, RoutingTraceabilityEvents.build_routing_timeline /
  station_statistics, MultiProcessTraceabilityEvents.build_timeline /
  station_statistics). A station that logs an identifier once on arrival
  otherwise reports a per-station dwell of 0; when set, each visit's end is the
  identifier's next station arrival (in multi_process, only for sequential
  visits -- parallel/overlapping visits keep their own span). Default unchanged.
add: opt-in production_day extended to the remaining shift-grouping methods that
  share _assign_shift -- ScrapTracking.scrap_by_shift, ReworkTracking
  (rework_by_shift, rework_rate), QualityTracking (nok_by_shift,
  daily_quality_summary), OperatorPerformanceTracking.production_by_operator --
  so an overnight shift is one contiguous (date, shift) group. Default (raw
  calendar date) unchanged.
add: opt-in max_gap on DowntimeTracking.downtime_by_shift / availability_trend
  and max_cycle_gap on CycleTimeTracking.cycle_time_by_part and
  PerformanceLossTracking (performance_by_shift, slow_periods,
  performance_trend). A duration taken as next-time minus time otherwise
  bridges logging gaps and stoppages: a logger outage is booked as uptime, and
  a lunch break becomes one giant "cycle" that reads as a huge speed loss.
  Durations above the cap are excluded as "no data". Default (None) unchanged.
add: opt-in time_weighted on BottleneckDetectionEvents.station_utilization
  (and detect_bottleneck / shifting_bottleneck / throughput_constraint_summary)
  and DutyCycleEvents.duty_cycle_per_window. resample().mean() averages sample
  counts, so on change-encoded/irregular signals a station up all hour but
  logged once reads 50-100% by row count; time_weighted weights each sample by
  the gap to the next sample. Default (sample mean) unchanged.
fix: LineThroughputEvents.cycle_quality_check returned inf/NaN deviations when
  the expected cycle time was zero (explicit, or a degenerate zero median); it
  now returns the typed empty frame.
add: ts_shape.utils.shifts (assign_shift, production_dates) -- shared shift
  assignment plus a "production day" that attributes an overnight shift's
  post-midnight readings to the shift's start date. Grouping a night shift
  (22:00->06:00) by raw calendar date splits it across two dates and, within a
  date, spans the whole day so last - first sweeps in other shifts' output
  (a night shift could report ~750% of target).
add: opt-in production_day=True on TargetTracking.compare_to_target,
  ShiftReporting.shift_production, and ShiftHandover.generate_report so overnight
  shifts group as one contiguous interval. Default (calendar date) unchanged.
add: opt-in require_all_stations=True on LineBalancingEvents.balance_metrics so a
  fully stopped station stays in the denominator (a dead station previously read
  as a perfectly balanced line); adds a stations_missing column.
add: opt-in count_initial_active=False on AlarmManagementEvents.alarm_frequency
  to ignore an alarm already active at the start of the data window.
add: ts_shape.utils.intervals.state_intervals -- shared helper that collapses a
  state signal into intervals and closes each one at the next transition when
  interval_end="next_change". The previous "end at the last sample carrying the
  state" logic collapses to zero duration on change-encoded (is_delta) signals
  -- one row per transition -- so downtime, micro-stop and duty-cycle analyses
  silently reported nothing on the library's normal data shape.
add: opt-in interval_end="next_change" (with an optional data_end bound for the
  final open interval) on MachineStateEvents.detect_run_idle /
  state_quality_metrics and LongDowntimeEvents.detect_long_downtime, and as a
  constructor option on MicroStopEvents and DutyCycleEvents. Default
  ("last_sample") is unchanged. On change-encoded signals this recovers
  micro-stop lost time, multi-hour downtimes, and on/off durations that
  previously read as zero. (Traceability dwell shares the collapse but has
  distinct cross-station semantics and is a separate follow-up.)
add: ts_shape.utils.counters (counter_quantity, counter_increments,
  count_resets) -- shared reset-aware handling for monotonic production
  counters that reset to zero at a shift/part change or PLC restart. A naive
  last - first loses all production in a window where a reset happened.
add: opt-in handle_resets=True across the production pack so the reset-aware
  behaviour shipped in PartProductionTracking is available everywhere a
  quantity is derived from a counter: OEECalculator (calculate_performance,
  calculate_quality), LineThroughputEvents.count_parts, TargetTracking,
  ScrapTracking, ReworkTracking, QualityTracking, BatchTrackingEvents,
  OperatorPerformanceTracking, ContinuousProcessAlignment.segment_by_cut,
  ShiftReporting, ShiftHandover, and PeriodSummary. Default behaviour and
  column sets are unchanged; when enabled the result gains a resets column.
  For the by-reason / by-part methods this also corrects the over-count that
  last - first produces when categories alternate over a non-contiguous group.
fix: DowntimeTracking.downtime_by_reason booked running time as downtime (it
  diffed timestamps after filtering to stopped rows, so a stop lasted until
  the next stop). Duration is now computed on the full state timeline before
  filtering, mirroring downtime_by_shift.
fix: QualityTracking.daily_quality_summary returned NaN rates for a zero-total
  day (0/0); both rate divisions are now guarded to 0.0.
fix: LineThroughputEvents.throughput_oee produced NaN/inf performance when the
  target rate was zero (flat counter or explicit 0); it now reports 0.
fix: ShiftReporting.shift_targets produced inf achievement_pct for a zero
  target; now guarded to 0.0, matching ShiftHandover.
add: ChangeoverEvents.detect_changeover gained include_initial (default True
  preserves the current behaviour of emitting the first reading; pass False to
  report only real value changes and drop the synthetic leading event).
docs: docs/production_gap_screening.md -- a full functional-gap screen of the
  production pack, with the remaining themes (interval-duration on
  change-encoded signals, gap-spanning durations, time-weighted utilisation,
  overnight-shift attribution) lined out as scoped follow-ups.

# June 2, 2026
changed: event-log output now trims entirely-empty extra columns. The 9
  canonical core columns (ocel:eid, ocel:activity, ocel:timestamp,
  ts_shape:start_timestamp, ts_shape:duration_s, ts_shape:detector,
  ts_shape:pack, ts_shape:severity, ts_shape:value) are always emitted, so
  every event log keeps an identical append-friendly core schema; per-detector
  extras (<pack>:<col> passthroughs, standard-attr extensions) are dropped when
  all-empty instead of shipped full of NaN.
add: align_columns(*logs) -- reindex multiple EventLogs' events tables to their
  shared column union (core first, extras sorted) so each frame exposes an
  identical column set before appending/stacking. concat(...) already unions
  columns on merge; this is for callers stacking frames themselves.
changed: event-log exporters renamed for a consistent to_event_log* family:
  to_flat_df -> to_event_log_xes, to_ocel_tables -> to_event_log_ocel. The old
  names remain as deprecated aliases (DeprecationWarning) for back-compat.

# May 20, 2026
add: Pipeline -- the single declarative orchestrator for ts-shape. Chains
  transform and detector steps into one reusable definition: .transform()
  steps replace the working signal; .detect() steps store named event
  results. Supports $input/$prev sentinels for multi-DataFrame wiring,
  run_steps() for intermediates, describe() for previews, and
  PipelineResult.to_event_log() for combined OCEL export.
BREAKING: removed FeaturePipeline (features.segment_analysis.feature_pipeline);
  Pipeline replaces it. Migration: FeaturePipeline(df)...run() becomes
  Pipeline()...run(df); .add_step(Cls.method, **kw) and
  .add_instance_step(Cls, call='method', **kw) both become
  .transform(Cls, 'method', **kw); .add_lambda_step(fn) becomes
  .transform(fn). $input/$prev sentinels and run_steps() are unchanged.
add: UnitConverter -- engineering unit conversion (transform), a thin wrapper
  around the pint library. Optional extra: pip install ts-shape[units].
add: RuntimeAccountingEvents -- operating-hours accounting (total run time,
  start count, longest run, utilization, per-window runtime, hour-meter).
add: LineBalancingEvents -- line balancing & takt analysis (station cycle
  times, balance efficiency/delay, smoothness index, theoretical minimum
  stations, Yamazumi station-loading table).
add: FlowMetricsEvents -- flow analytics (time-weighted WIP, throughput,
  FIFO lead time, Little's Law consistency check, Process Cycle Efficiency).
add: ts_shape.make_timeseries() -- public synthetic-data generator for trying
  detectors and transforms without real data or loaders.
add: ts_shape.list_detectors() -- programmatic catalog of every top-level
  class, grouped by pack/category.
add: Base.__repr__ -- detector and instance classes now print a useful
  summary (row count + configured uuid/value_column).
changed: OutlierDetectionEvents emits the canonical point shape (systime,
  uuid, source_uuid) via events/_output.py -- completes the May 14 output
  standardization. uuid carries the event id, source_uuid the source signal.
changed: event detectors validate their configured UUID up front
  (Base._validate_uuid) -- a typo'd UUID now raises a clear error listing the
  available UUIDs instead of silently returning empty results.
fix: DatapointAPI HTTP requests now send a timeout (default 30s) so an
  unresponsive server can no longer hang the loader.
fix: TimescaleDBDataAccess uses bound SQL parameters instead of f-string
  interpolation.
fix: CycleExtractor uses Base's sorted, defensive copy -- it no longer
  mutates the caller's DataFrame.
fix: README quick-start and pack examples corrected to match real
  constructor signatures (SPC, ToleranceDeviationEvents, DataIntegratorHybrid,

# May 14, 2026
BREAKING: event-detector outputs standardized across all packs (quality,
  production, engineering, maintenance, supplychain, energy, correlation).
  Every public DataFrame-returning method now emits one of three canonical
  shapes: point (systime), interval (start, end, duration_seconds), or
  summary (start, end, duration_seconds + aggregate columns).

  Column renames applied uniformly:
    start_time, gap_start, window_start, period_start, disturbance_start
      -> start
    end_time, gap_end, window_end, period_end, disturbance_end -> end
    severity_score, severity_level -> severity
    OEECalculator: date -> start + end + duration_seconds (86400)

  New helpers in src/ts_shape/events/_output.py (empty_event_df,
  finalize_point_df, finalize_interval_df, finalize_summary_df) define
  the canonical column constants and empty-frame schema.

  ts_shape.eventlog.adapters.adapt no longer probes legacy column name
  variants -- it expects the canonical names. The taxonomy registry has
  been updated (severity_field="severity"). See docs/guides/eventlog.md
  for the simplified shape table.

  Downstream code asserting old column names must be updated.
